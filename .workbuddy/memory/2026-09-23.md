## 修正昨天的「封面圆角」修法（用户实拍第二次揪出来）

用户贴了磁贴左上角的放大截图：「圆角不对劲」。放大像素采样后确认：
**封面色块把磁贴的墨色描边整个盖住了** —— 描边只剩一条抗锯齿的灰毛边
（实测角部描边像素是 `c9c7be`/`84827a` 的浅灰，而不是 `221f1a` 的墨色），
圆角弧线跟着糊掉。

**昨天的修法（磁贴 `clip_children = CLIP_CHILDREN_AND_DRAW`）是错的理解：**
`clip_children` 只能切掉「出界」的部分（方角冒出圆角外），但 Godot 里
**子节点永远画在父节点 StyleBox（含描边）之上** —— 封面铺满内容区
（`content_margin=0`），把描边压在身下，裁剪根本救不了描边。

**正确修法 = 照 CSS 语义直译**（`hud.gd:_cover_slot()`）：
1. 封面板四边**收进描边内壁** `STROKE`（3px）：`offset_left/top = STROKE`、
   `offset_right = -STROKE`（底部不收，由那条墨色收边线收口）——
   通栏的「贴边」效果不变，因为色块紧贴描边内侧。
2. 封面板**自己带同心圆角**：上面两个角 `TILE_RADIUS - STROKE`（28−3=25，
   与外圆角 28 同心），下面两个角 0。
3. **裁剪下放到封面层**：`plate.clip_children = CLIP_CHILDREN_AND_DRAW` ——
   玩法画的封面色块被裁成圆角，而磁贴的描边在这一层之上、谁也盖不到。
4. 删掉磁贴层的 `clip_children`（`ui_kit.gd:tile()`），注释说明为什么不能放那。

**实拍确认**：角上是清晰的墨色描边 + 干净的同心弧，粉色封面贴着描边内壁走。

**通用教训（取代昨天的说法）**：
- Godot 里「圆角容器 + 铺满子色块」要圆角，**不能只靠父级 `clip_children`** ——
  它管不住「子节点盖住父级描边」。正确姿势：子块收进描边内壁 + 自带同心圆角 +
  裁剪放在子块那一层。
- 内弧半径 = 外圆角 − 描边宽（Godot 的 StyleBoxFlat 描边画在弧内侧，
  `flat_box` 不会自动帮你算）。
- **编辑器没开时也能实拍**：直接 `godot --path . -- --simulate --sim-players=4`
  拉起游戏（要带用户图形会话的环境变量：`DISPLAY/WAYLAND_DISPLAY/XAUTHORITY/
  XDG_RUNTIME_DIR/DBUS_SESSION_BUS_ADDRESS`，从 `plasmashell` 的
  `/proc/<pid>/environ` 读），再 `spectacle -b -n -o <file>` 全屏截图 +
  Pillow 按奶油纸特征色定位窗口裁剪放大。Wayland 不认 `--position`，
  窗口位置要用特征色扫描找。

## 拔河 TUG-01 / TUG-02：玩法改「往上蹦」+ 对局屏重构

### TUG-01 · 输入通道从「挥动 + 倾斜」换成「连续蹦」
用户拍板：「倒计时 5 秒 / 对局屏只留顶部一条 / 传感器拉手机改成往上蹦」。
追问后明确三件事：**倒计时 5 秒**；**对局屏只要顶部细条（时间+比分）**；
**「往上蹦」= 连续蹦、越密拉力越大**（不是「一次动作 = 一记拉力」）；
**去掉「持续倾斜 = 慢慢蹭」通道，只留蹦**。

实现（`input/motion_filter.gd`）：
- 挥动检测改成**只认向上**：`accel.y` 高出「自身慢速均值」才算向上。
- 新增 `jump: float`（连续强度）—— 冲高时取 max，不蹦按 `JUMP_DECAY_PER_SEC * dt` 衰减。
- `_last_ms` 自记算 dt（首包 dt=0）。
- 事件 `{"type":"swing"}` → `{"type":"jump"}`；删 `swing_power`。
- `tilt` / `calibrate()` / `reset()` **保留**（倾斜能力没删，见下）。

**⚠️ 密度反转 bug（自检抓出来的，会漏到真机）**：
新增「同冲量越密越强」判据首跑**反了**（密 0.00 vs 疏 0.11）。
根因：慢速均值被密集冲量的尾巴抬高 → 冲量（`accel.y` − 均值）变小 → 反而冲不过阈值。
即「小孩蹦越快越推不动」。修法：**冲高期冻结基线；非冲高时基线向下跟快、向上跟极慢**
（`JUMP_EMA_RISE := 0.0005`）。修后 8 秒实测：密 0.87 / 中 0.58 / 疏 0.27，单调正确。

玩法侧（`minigames/tug/tug_of_war.gd`）：删 `PULL_PER_SWING/SWING_POWER_FLOW/TILT_PULL_PER_SEC`，
新增 `JUMP_PULL_PER_SEC := 0.30`，`tick()` 合并成一行
`rope += dir * JUMP_PULL_PER_SEC * s.jump() * delta`；`pulls` → `jumps`。
`core/game_flow.gd`：`COUNTDOWN_SEC := 3.0` → **`5.0`**。
`sim/simulator.gd` + `main.gd`：`enable_swing/swing_period/SWING_DECAY` → jump 命名。
同步改：`player_session.gd`（加 `jump()`）、`minigame_selftest.gd`、`fake_game.gd`、`tug_selftest.gd`、`selfcheck.gd`。

**倾斜通道现状（用户问过）**：拔河**已不消费**倾斜（常量删除、`tick()` 不读 `tilt()`），
但输入层能力完整保留。建议**先不加回** —— 倾斜一旦有收益，「歪着拿住不动」就是最优解，蹦就废了。
更好的用法是让它和蹦**分工**（倾斜控方向、蹦控拉力），但那是另一个玩法。

### ⚠️ 认证踩坑（重要，别再走弯路）
1. **HTTPS 推不了**：`could not read Username for 'https://github.com'` ——
   GitHub 2021 起不收密码，要 PAT（Personal Access Token），而他**没配 credential.helper**
   （`credential.helper` 为空、无 gh CLI）。所以别推荐 HTTPS 路线。
2. **`ssh -T git@github.com` 一开始 `Permission denied (publickey)`**，我以为是没密钥，
   `ssh-keygen` 生成了 `~/.ssh/id_ed25519_github`。**这是白做的**：
   - 他 `SSH_AUTH_SOCK=/run/user/1000/gcr/ssh` —— 密钥是 **GNOME Keyring 代管**的（不在磁盘）。
   - keygen 推出的新钥匙公钥**和 keyring 里那把字节完全相同**（指纹
     `SHA256:Ro7pk8pT9kqx4MaskNOYerdZpXsYAq5jEr+1lbKj8Ac`），因为派生同源。
   - **但 GitHub 上没注册它** → 依然被拒。**密钥存在 ≠ 已授权。**
3. **真正的钥匙是 `~/.ssh/zm.pem`**（RSA 2048，9月14日就在，
   私钥头 `-----BEGIN RSA PRIVATE KEY-----`）。用户提示「用密钥」→「zm 这个」后测通：
   ```
   ssh -o IdentitiesOnly=yes -o IdentityFile=~/.ssh/zm.pem -T git@github.com
   → Hi 121ZM! You've successfully authenticated, but GitHub does not provide shell access.
   ```
   指纹 `SHA256:3RBD2/hqyC/FfmVVHo374ZDHRS8zRvKAeuJYfoFkgTM`。
4. 写 `~/.ssh/config`（**原本没有这个文件**，新建的）：
   ```
   Host github.com
       HostName github.com
       User git
       IdentityFile ~/.ssh/zm.pem
       IdentitiesOnly yes
   ```
   `IdentitiesOnly yes` 是关键 —— 不加的话 agent 里那把未注册的钥匙会先被试，干扰判断。
5. 删掉白生成的 `~/.ssh/id_ed25519_github*`（与 keyring 重复）。

### 结果
`git push -u origin main` 成功，`origin/main` = 本地 HEAD = `a85a6f2`，
`main...origin/main` 无差异，跟踪关系已建立。以后直接 `git push`。

**通用教训**：`ssh -T` 被拒先别急着 keygen ——
**先 `ssh-add -l` 看 agent 里有什么、再看 `~/.ssh/` 里有哪些已存在的 `.pem`/私钥**，
逐个用 `-o IdentitiesOnly=yes -o IdentityFile=<path>` 试。**存在 ≠ 已授权**，
但已授权的往往早就在磁盘上躺着了。

### SDK 安装踩的 3 个坑（已全部解决，脚本 `controller/tools/setup_flutter_ohos.sh`）
1. **归档下载地址全是 HTML** —— atomgit/gitcode 的 `archive/<ref>.tar.gz`、
   `releases/download/...`、`api/v5/.../tarball` 三种都返回网页或 401/404。
   **唯一可靠路径：`git clone --branch oh-3.35.7-release`**。
2. **浅克隆 → 版本号变 `0.0.0-unknown` → `pub get` 依赖解析失败**
   （报 `flutter_test requires Flutter >=3.18.0`，看着像依赖冲突，其实是版本没解析）。
   修法：`git tag 3.35.7` 补 tag + 删 `bin/cache/flutter_tools.stamp` 重算。
3. **`flutter test` 静默 exit**（只打一行 `[!] No Hmos SDK found.`，**一个测试都不跑**，
   极易误判成「测试通过」）。根因：`flutter_tools/lib/src/project.dart` 的
   `ensureReadyForPlatformSpecificTooling()` 调 `hvigor.updateLocalProperties()`
   时 `requireHarmonySdk` 默认 true，没鸿蒙 SDK 就 `throwToolExit`。
   **已在 SDK 源码打补丁**改成 `requireHarmonySdk: false`（编 hap 的路径另有检查，不受影响）。
   ⚠️ 升级 SDK 会覆盖，重装必须重跑脚本。

### 测试抓到的真 bug（值得记）
`ControllerSession.dispose()` 里 `unawaited(disconnect())`，
而 `disconnect()` 尾部会 `_setState()` → `notifyListeners()`，
**在 dispose 之后调用直接抛「used after being disposed」** —— 真机退 App 时会崩。
修法：加 `bool _disposed` 标志，`_setState` 与定时器回调都先判。
**顺手修了传感器订阅泄漏**：原来 `_sensor.samples.listen()` 没存句柄，
断开后流还在推，重连会挂多个订阅导致读数翻倍 → 改成保存 `StreamSubscription` 并在 disconnect 里 cancel。
