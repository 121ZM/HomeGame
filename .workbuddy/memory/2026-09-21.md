## 项目启动：Godot 体感游戏（HomeGame）

- 讨论体感游戏方案，梳理出三条输入路径：手机/平板传感器、摄像头视觉识别、专用体感硬件。
  **核心结论**：Godot 侧应先行「统一输入抽象层」——把所有体感信号归一化为自定义 InputEvent，
  玩法层只订阅事件、不认来源，避免识别管线与玩法逻辑耦合。方案待用户回答三问（输入源 / 平台 / 玩法方向）后落地。
- 环境就绪：安装 **Godot 4.7.2-stable 标准版**（非 .NET）到 `~/DEV/godot-4.7.2-stable/`，
  启动器 `~/.local/bin/godot` + 桌面项 `godot.desktop` + 官方彩色图标均已配齐，`--headless --version` 验证通过。
- 选标准版而非 .NET 版的理由：体感 API（陀螺仪/加速度计）在 GDScript 里都是原生一句调用，
  社区教程与示例也以 GDScript 为主；.NET 版还多一层 .NET SDK 依赖。

## 第一阶段完成：大屏端骨架 + 数据链路验证

- 用户选定：**输入源 = 手机传感器**，**游戏跑在 PC / 电视**，**网络 = 局域网**（家庭 WiFi）。
- 目录结构：`/home/zm/DM/HomeGame/{screen,controller}` —— 两个**平级** Godot 项目（Godot 项目不能嵌套），
  当前只做了 `screen/`（大屏端），`controller/`（手机端 App）留空待第二阶段。
- 代码分层（`screen/scripts/`）：
  - `net/motion_packet.gd` —— 协议编解码，固定 **38 字节小端**：magic 0xA7 / version / player_id(u16) /
    seq(u32) / gyro 3×f32 / accel 3×f32 / buttons(u16) / timestamp_ms(u32)
  - `net/udp_server.gd` —— UDP 监听（必须绑 `0.0.0.0`/`"*"`）、会话管理、3s 超时离线、丢包统计
  - `net/player_session.gd` —— 单玩家状态 + 链路质量
  - `input/motion_filter.gd` —— **输入抽象层**：低通滤波 → 死区 → 挥动事件识别，带零点校准 `calibrate()`
  - `sim/simulator.gd` —— 模拟手机端，造带噪声的正弦倾斜 + 每 3 秒一次衰减挥动脉冲
  - `main.gd` —— 代码构建 3D 视图 + HUD，不依赖手写 tscn
- **验证结果（headless 实测通过）**：
  - 单进程自测：60Hz 稳定收包，12s 收 726 包，丢包 0，异常包 0，抓到 4 次挥动（power≈0.56–0.60）
  - 双进程测试（`main.tscn` 与 `tools/simulator.tscn` 两个独立进程）：收包正常，
    模拟器退出后 3s 内正确判定超时离线
- **关键坑**：`godot --headless --path . --quit` **不会生成 `.godot/`**，全局 `class_name` 解析不到，
  报 `Could not find type "UdpServer"`。必须先用 **`--import`** 跑一次初始化。
- 运行命令：
  - 带画面 `godot --path screen`
  - 自测 `godot --headless --path screen res://scenes/main.tscn -- --simulate`
  - 双进程：接收 `... res://scenes/main.tscn`，发送 `... res://tools/simulator.tscn`
