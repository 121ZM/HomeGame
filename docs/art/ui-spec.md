# HomeGame 大屏 UI 视觉规格（UI-01）

> 依据：`screen/scripts/core/ui_kit.gd`、`screen/scripts/ui/hud.gd`、
> `screen/scripts/core/player_palette.gd` 与真实运行截图
> `/home/zm/.cache/hg-shots/decouple/01_t6_0s.png`（大厅 4 人）。
> 基准分辨率 1920×1080，客厅 55 寸电视、观看 2–3 米、亲子、键盘/遥控器（无鼠标）。
> 本文件只定规格，不改代码。所有像素值都是 1080p 基准下的值。

---

## 0. 现状诊断（截图 + 代码读出来的问题）

1. **没有层次**：状态条、主卡、玩法卡、在座玩家卡全是同一套 39px 圆角 + 6/7px 描边，
   视线在屏上没有「先看哪」的引导 —— 这是「觉得粗糙」的最大来源。
2. **语义在借玩家的身份色**：
   - 在线圆点 = `PlayerPalette.color_for_slot(3)`（绿）
   - 倒计时牌底 = slot 4（紫）、答题牌底 = slot 5（橙）
   - 玩法卡的「可以开始」药丸 = slot 3（绿）
   家庭局里孩子会问「这块紫色是不是 5 号玩家的？」—— 身份色和状态色混用，两套语言都失真。
3. **对比度有一处不达标**：开不了的原因药丸（`PILL_MUTE` 底 + `INK_SOFT` 字，32px）
   实测约 3.3:1，低于正文 4.5:1 下限；而这句恰恰是家长必须读的。
4. **间距不成体系**：44 / 30 / 18 / 27×12 各是各的，没有可推导的节奏。

---

## 1. 视觉身份 · 三条支柱

1. **贴纸分大小，描边分轻重。**
   「好看」第一指**有主次**：一屏只有一个焦点件用最粗描边 + 最大圆角（倒计时牌、结算牌、
   选中玩法卡），容器件退半档，标签再退半档。层次靠这三档描边/圆角表达，不靠投影和渐变
   （平涂原则不变）。
2. **颜色只说两件事：身份归玩家，状态归系统。**
   8 色药丸永远只指「这个人是谁」；「能不能开始 / 在不在线 / 紧不紧急」一律走语义色表
   （§2.1），两者一个 hex 都不许互借。每个颜色信号必须伴生文字或符号（§6）。
3. **一屏一件事，其余往后退。**
   大厅的唯一焦点是玩法卡网格，对局的唯一焦点是右侧舞台；标题、说明、链路统计全部用
   弱化色和小一档字号往后压。奖励「好看」的手段是留白和字号对比，不是给每块都加框。

## 2. 令牌表（可直接抄进 `ui_kit.gd`）

### 2.1 色板

**保留不动**（现有底座是对的）：

| 令牌 | hex | 用途 |
|---|---|---|
| `PAPER` | `#fffdf5` | 卡片底 |
| `INK` | `#23232b` | 描边、正文、选中反白底 |
| `INK_SOFT` | `#6f6f80` | 次要文字 |
| `PAPER_DIM` | `#e9e5d9` | 未选玩法卡底 |
| `DIVIDER` | `#d8d3c4` | 卡内分隔线 |
| `SCRIM` | `#14141a99` | 结算遮罩 |
| `PILL_MUTE` | `#d5d1c4` | 无身份药丸底 / 离线点 |

**新增语义色**（刻意都与 8 色身份表的 hex 错开）：

| 令牌 | hex | 使用规则 |
|---|---|---|
| `SEM_OK` | `#188a52` | **在线圆点**、**「可以开始」药丸底**。比身份绿 `#2fbf71` 深一档；只许配白字，只许出现在药丸/圆点这种小面积上 |
| `SEM_OFF` | `#d5d1c4` | 离线圆点（= `PILL_MUTE`，单独立名是为了语义可查） |
| `SEM_BLOCKED` | 底 `PILL_MUTE` + 字 `INK` | 「开不了」及原因药丸。**字从 `INK_SOFT` 提到 `INK`**（修 3.3:1 问题）；不许用警示橙 —— 人不够不是错误 |
| `SEM_WARN` | `#d9722c` | 保留现有 WARN。橙字白底用；也作为倒计时底色（同族 = 「注意」） |
| `SEM_COUNTDOWN` | `#d9722c` | 倒计时牌底 + 白字。倒计时数字 192px、提示 54px，白字对它 3.3:1，满足大字 3:1 下限；**此色只许配 ≥54px 的字** |
| `SEM_ANSWER` | `#6d3fc4` | 答题/奖励牌底 + 白字（白字 6.6:1）。全场唯一用紫的地方，一眼知道「现在不是正常对局」 |
| `RESULT_WIN` | = `PlayerPalette.color_for_team(胜队)` | 结算-胜：牌的**描边 + 标题字色**用胜队色（红/蓝在纸底上 ≥3.7:1，84px 大字达标）。队伍色在这里是「哪队赢了」的语义，允许 —— 结算是对局语言的终点 |
| `RESULT_DRAW` | `INK` | 结算-平：墨色描边 + 墨色标题，不加任何彩色 |

> 取代方案：`hud.gd` 里 `_update_status`（slot 3）、`_update_stage`（slot 4/5）、
> `_game_card`（slot 3）共四处改为引用语义令牌。**玩家药丸、队伍拔河地界、结算胜队
> 描边三处继续用 PlayerPalette，不受影响。**

### 2.2 字阶：全部保留，只加使用规则

现有六档（192 / 84 / 54 / 39 / 32 / 27）是按 2–3 米观看距离校准过一轮的
（BODY 曾从 20 提到 39），数值本身没有问题，动它只有回归风险没有观感收益。
只补三条**使用规则**：

| 字号 | 规则 |
|---|---|
| `FONT_HUGE` 192 | 只给倒计时数字 |
| `FONT_TITLE` 84 | 大厅标题、结算标题、答题牌标题 |
| `FONT_BIG` 54 | 玩法名、倒计时牌提示行 |
| `FONT_BODY` 39 | 正文、状态条人数、玩家必须读的一句话 |
| `FONT_SMALL` 32 | 说明、人数区间、操作提示 —— **玩家应读信息的下限** |
| `FONT_MICRO` 27 | 只许链路统计这类调试角标，**禁止承载玩家需要读的内容** |

### 2.3 圆角与描边 · 三档层级表（核心改动）

| 层级 | 用途 | 描边 | 圆角 | 内边距 | 现状 → 目标 |
|---|---|---|---|---|---|
| **L1 焦点** | 选中玩法卡、倒计时牌、答题牌、结算牌 | `STROKE` 7 | `RADIUS_L1` 39 | `PAD_L1` 32 | 30→32 |
| **L2 容器** | 状态条、信息主卡、在座玩家卡、未选玩法卡 | `STROKE_THIN` 6 | `RADIUS_L2` **27（新）** | `PAD_L2` **24（新）** | 全是 39/30 |
| **L3 标签** | 玩家药丸、状态药丸 | 6（不变） | 半高 33（不变） | `PILL_PAD` 24×10（现 27×12） | 微收 |

规则：圆角跟着描边走 —— 粗描边配大圆角，细描边配小圆角，混搭会显脏。
`flat_box()` 默认参数改为 L2 档，L1 在调用处显式传。

### 2.4 间距节奏 · 8 的倍数体系

间距只用这五个值：**8 / 16 / 24 / 32 / 48**。

| 令牌 | 现 | 目标 | 说明 |
|---|---|---|---|
| `MARGIN` | 44 | **56** | 页边距。44 < 54px（1080p 的 5% overscan 下限，见 §6.4），56 同时满足 8 系和安全区 |
| `GAP` | 18 | **16** | 同组元素间距（卡内行距、药丸间距） |
| `PAD_L1` | 30 | **32** | 焦点卡内边距 |
| `PAD_L2` | 30 | **24** | 容器卡内边距 |
| 区块间距 | — | **24** | 大厅「主卡 ↔ 在座玩家卡」之间（比 GAP 大一档） |
| 卡内「标题 ↔ 分隔线」 | — | **8** | 标题贴着自己的内容，不跟别的东西等距 |

玩法卡最小高 196 → **200**；`RESULT_WIDTH` 1350 保持（宽度是布局值不入节奏表）。

## 3. 组件规格

### 3.1 状态条（两屏各一份，画法相同）

L2 卡，横贯全宽（大厅）/ 左栏顶（对局）。单行三段：

| 元素 | 规格 |
|---|---|
| 圆点 | 直径 22→**24**，在线 = `SEM_OK`，离线 = `SEM_OFF` |
| 「在线 N / M」 | `FONT_BODY`，`INK` |
| 链路统计（右对齐） | `FONT_MICRO`，`INK_SOFT` —— 唯一允许用 MICRO 的地方 |

### 3.2 玩法卡（2 列网格，最小高 200，四状态矩阵）

结构（自上而下）：`序号/▶ 药丸 + 玩法名 + 人数区间` → 分隔线 → `状态药丸`（行尾撑开）。

| 状态 | 底 | 描边/圆角 | 玩法名 | 序号药丸 | 状态药丸 |
|---|---|---|---|---|---|
| 未选 · 可开 | `PAPER` | 6 / 27（L2） | `INK` BIG | `PILL_MUTE` 底 + 槽位号 | `SEM_OK` 底白字「可以开始」 |
| 未选 · 开不了 | `PAPER_DIM` | 6 / 27（L2） | `INK` BIG | `PILL_MUTE` 底 + 槽位号 | `PILL_MUTE` 底 + **`INK` 字**（原因） |
| 选中 · 可开 | `INK` 反白 | **7 / 39（L1）** | 白 BIG | 白底 + `▶` | `SEM_OK` 底白字 |
| 选中 · 开不了 | `INK` 反白 | **7 / 39（L1）** | 白 BIG | 白底 + `▶` | **`SEM_WARN` 底白字**（原因）—— 选中却开不了是当场最该看见的信息，给最高警示级 |

选中态保持墨色反白（不用彩色，理由照旧：不跟身份色打架）。
选中卡的圆角/描边升到 L1，是「光标在哪」的第三个信号（另两个：反白 + ▶）。

### 3.3 在座玩家药丸

- **加槽位号，不加头像位。** 药丸左端加一枚 36px 圆徽：`INK` 底白字槽位号，
  右侧接玩家色药丸底 + 名字。槽位号是排障刚需（手机连上后对号），名字已解决色弱辨识，
  头像无图片资源可做、家庭局名字也足够 —— 不做。
- 药丸底色只用 `PlayerPalette`，描边 `INK` 6px，圆角半高，内边距 24×10。
- 「槽位 N 空」保持 `PILL_MUTE` 底 + `INK_SOFT` 字（32px，次要信息，允许）。
- 大厅每行 4 个、对局左栏每行 2 个的网格布局不变。

### 3.4 结算牌

全屏 `SCRIM` 遮罩不变。居中牌宽 1350，L1 档（7 / 39 / 32），行距用 `GAP*2` → **32**。

| 场景 | 描边 | 标题字色 | 前缀图形 |
|---|---|---|---|
| 有胜队 | `PlayerPalette.color_for_team` | 同色 | 独立 Label「★」`FONT_TITLE` 同色，置于标题上方居中 |
| 平局 | `INK` | `INK` | 无 |

细节行：`FONT_BODY` `INK_SOFT`，破折号切分的逻辑不动。

### 3.5 倒计时牌（舞台居中浮层）

L1 卡，底 `SEM_COUNTDOWN`（橙）描边 `INK` 7。数字 `FONT_HUGE` 白、居中；
提示行 `FONT_BIG` 白。位置、出现时机（仅此一刻才浮上来）不变。

### 3.6 答题牌（舞台靠上浮层）

L1 卡，底 `SEM_ANSWER`（紫）描边 `INK` 7。标题 `FONT_TITLE` 白、正文 `FONT_BODY` 白、
提示行 `FONT_SMALL` `#ffe8c9`（保留现有暖白，紫底上 8:1+）。仍靠上不挡绳子。

## 4. 图标与图形语言

**零图片资源**。可用材料仅三样：`Panel`/`ColorRect` 平涂几何（点、圆徽、分隔线、
`StyleBoxFlat` 圆角矩形）、`Polygon2D`（预留，目前无需要）、**字体字形**。

### 4.1 可用符号清单（及使用场合）

| 字形 | 含义 | 场合 |
|---|---|---|
| `▶` | 光标 / 即将开始 | 选中玩法卡的序号药丸（替代数字） |
| `★` | 胜利 | 结算牌标题前缀，**仅胜局** |
| `⚠` | 警示 | 大厅 hint 行前缀（现有用法保留） |
| `↑` `↓` `回车` `数字` | 操作提示 | 大厅标题右侧（现有文案不动） |
| `·` `—` | 分隔/破折号 | 行内分隔、结算细节前缀（现有） |

**禁用**：emoji（跨设备渲染不可控）、✔ ✕ ⚡ ◆ 等覆盖不稳的字形（见风险 §7）。
圆点/圆徽一律用 `Panel` 平涂画，不用 `●` 字形（垂直居中不可控）。

### 4.2 图形语法

- 几何词汇只有三种：**圆角矩形（卡）、半高胶囊（药丸）、正圆（点/徽）**。
  不出现新形状 —— 需要新形状 = 设计越界，先回这改规格。
- 平涂铁律不变：无渐变、无投影、无描边外发光；`SCRIM` 是唯一的半透明。

## 5. 动效（四条，全部 Godot Tween，成本一条 ≈ 10 行）

总原则：**单次、短促、无循环**（倒计时数字 pop 除外）；任何动效 ≤ 0.3s；
只挂在浮层/卡片「首次出现」的时机 —— `hud.gd` 的内容指纹机制不变就不重建，
动画挂在 sig 变化后的那次填充即可，天然不会每帧重播。

| # | 场景 | 做法 | 时长/缓动 |
|---|---|---|---|
| A1 | 入场（倒计时/答题浮层、结算牌） | `scale` 0.92→1.0 + `modulate.a` 0→1，pivot 设卡片中心 | 0.16s `TRANS_CUBIC` `EASE_OUT` |
| A2 | 光标移动（玩法卡选中切换） | 新选中卡从 `scale` 0.96→1.0（节点是重建的，只补一个落定小弹） | 0.12s `TRANS_CUBIC` `EASE_OUT` |
| A3 | 倒计时跳数 | 数字 Label `scale` 1.0→1.15→1.0 两段；**数字色不加闪烁**（平涂 + 克制） | 0.20s `TRANS_BACK` `EASE_OUT` 出、`EASE_IN` 回 |
| A4 | 结算 | 遮罩 `modulate.a` 0→1；牌 `scale` 0.9→1.0 + `position.y` +24→0 | 遮罩 0.25s 线性；牌 0.30s `TRANS_BACK` `EASE_OUT` |

大厅主卡不做 A1：它随指纹频繁重建，加了会闪。

## 6. 可访问性

**定级：Standard**（家庭娱乐产品的合理目标；下表若全部落实，§6.1–6.4 实际已触及
Comprehensive 的主要条目，可在后续任务复评升级）。

### 6.1 色弱（红绿色弱人群约占男性 5%，亲子局必中）

规则：**任何语义不许只靠颜色**。落实为：

- 玩家药丸必带名字（已有）+ 槽位号徽（§3.3，红/绿药丸靠文字与号码区分）；
- 状态药丸必带文字（「可以开始」/ 原因，已有）；
- 在线/离线圆点配文字「在线 N / M」（已有）；
- 结算胜/平靠 ★ 有无 + 标题文字，不只靠队伍色描边。

### 6.2 对比度下限

| 文本级别 | 下限 | 现状核查 |
|---|---|---|
| 正文（≤39px） | 4.5:1 | `INK`/`PAPER` ≈14:1 ✓；`INK_SOFT`/`PAPER` ≈5:1 ✓ |
| 大字（≥54px） | 3:1 | 白/`SEM_OK` ≈4.4 ✓；白/`SEM_COUNTDOWN` ≈3.3 ✓（仅限 ≥54px）；白/`SEM_ANSWER` ≈6.6 ✓；队伍色标题/`PAPER` ≈3.7–3.9 ✓（仅限 84px 标题） |
| 需修复 | — | 原因药丸 `INK_SOFT`/`PILL_MUTE` ≈3.3 ✗ → 改 `INK`（§2.1 `SEM_BLOCKED`） |

### 6.3 最远观看距离下的最小字号

55 寸 1080p 在 3 米处，1px ≈ 1.2 视角弧分。规则：

- 玩家必须读的：≥ `FONT_SMALL` 32（≈38 弧分，冗余充足）；
- 凑近才看的：`FONT_MICRO` 27 仅限调试角标；
- **新增字号低于 27 一律拒绝** —— 那是显示器思维。

### 6.4 电视 overscan 安全边距

5% 安全区 = 水平 96px / 垂直 54px。当前 `MARGIN` 44 **垂直方向低于 54**，
老电视开「过扫描」会裁到状态条描边。**`MARGIN` 44 → 56**（≥54 且入 8 系）。

### 6.5 其他（Standard 级现状已满足）

无鼠标所以无悬停依赖；键盘/遥控器操作路径已有文字提示；无闪烁元素（A3 也不闪色）。

### 7.1 风险与验证

- **字形覆盖（最易被低估）**：`▶ ★ ⚠ ↑ ↓` 依赖系统字体回退。Godot 4 在 Linux 桌面
  有系统回退，但**导出到精简系统（盒子/Steam Deck 模式）可能变豆腐块**。发布前必须在
  真机看一眼这五个字形；如引入字体文件（可选方案），需核对许可证与导出体积。
